A phone-first web app (HTML, CSS, JavaScript, Tailwind) talks to a small Python Flask server on your laptop. The server keeps everything in one database file, watches deadlines every hour, and sends real reminder emails through Gmail using SMTP.

The reminder rule

From reminders.py, which runs on every save and every hour. Implements prd.md › Reminder Emails.

2 daysEmail: "renews in 2 days"
1 dayEmail: "renews tomorrow"
TodayEmail only if just saved and nothing sent yet (the demo)
PastNo email. Shows under Needs attention in the app

Smart writes down which reminder it sent (last_reminded_days), so it never sends the same one twice. Cancelled stops reminders. Renewed clears that note so reminders start again for the new date.

How the email gets sent

This is what you said you want to learn. It all happens in mailer.py, using tools built into Python.

  1. Find what's due. reminders.py picks the subscriptions whose reminder is due today.
  2. Write the email. Fill in the template: name, "renews tomorrow," the cancel link or the app's name, and an Open Smart button.
  3. Connect and log in. Connect to smtp.gmail.com:587, then starttls() to switch to an encrypted connection, then log in with your app password, which is read from .env.
  4. Hand it over. send_message(): from you, to the reminder address. Gmail delivers it.
  5. Remember it. Mark it sent. If anything failed, it isn't marked, so the next hourly check tries again.

Every PRD behavior has a home

Expand any of them to see the pieces and files.

Landing Page landing.js · app.js

Shown when the browser note smart_seen_landing is missing. The one button sets the note and goes to Home, so later visits open straight to Home.

Cards home.js · forms.js · POST /api/cards
  • Nickname, bank, name on card. No card number, ever.
  • Near-black card illustrations in a CSS scroll-snap carousel. When a new card snaps into view, the list below switches to it.
  • The network marks are decorative inline SVG.
Adding and Editing Subscriptions forms.js · POST/PUT /api/subscriptions
  • The card form opens over the subscription form, so nothing you typed is lost.
  • An inline email field appears if none is saved yet. The server also refuses to save without one.
  • Rows show trials first, then the soonest deadline. Time left is shown in days, or months once it's 60+ days away.
Monthly Totals format.js

Calculated in the browser from active subscriptions (trials included, cancelled ones excluded) every time the screen redraws. Money is stored in cents, so totals never drift.

Reminder Emails reminders.py · mailer.py · templates/email/

The rule and the SMTP steps above. The "Open Smart" button links to APP_URL (localhost for the demo).

In-App Reminder and the "Needs Check" Loop home.js · details.js · /cancel · /renew

Any active subscription with 2 or fewer days left, including past due, goes into Needs attention at the top. This is calculated, not stored, so it can't go out of date. "Yes, cancelled" sends it to history. "It renewed" asks for a date.

Profile profile.js · PUT /api/settings

The editable email, the overall total, the number of active subscriptions, the number of cards, and a link to history.

Cancelled History history.js

Name, card, and date cancelled, newest first. These never count toward totals.
